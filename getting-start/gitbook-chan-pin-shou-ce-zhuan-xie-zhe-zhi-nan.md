# Gitbook 產品手冊撰寫者指南

### 撰寫時機？

1. 於 Demo Meeting 展示新功能或優化後的功能後，PM 需要將此寫入 Gitbook
2. 當資訊錯誤回報發生時，當 Sprint 的 PM 值週生需要進行維護，將正確的資訊寫入 Gitbook
3. 當資訊缺漏回報發生時，當 Sprint 的 PM 值週生生協助判斷是否需要納入 Gitbook ，如判斷有其必要性，則將相關資訊寫入 Gitbook

### 新功能的操作與介紹撰寫流程

在功能所在介面分類裡新增操作模板頁，撰寫後將操作情境納入情境分類目錄，最後撰寫介紹說明頁，並將說明頁納入該情境分類目錄與該使用者的名詞解釋集合頁。

e.g. APP 推播管理：在課程管理介面/遊戲設置裡新增 **APP 推播管理**頁面，操作頁有四個操作情境：新增、編輯、查看、刪除 APP 通知，判斷四個情境是否有對應到的情境分類，如沒有，則新增情境分類並納入**後台使用情境**中對應到的情境分類。因為 APP 推播並非遊戲主要功能，因此需要在名詞解釋中找到**對應使用者分類**：管理者，並在該分類下新增 APP 推播通知的名詞解釋頁。最後，將名詞解釋頁的連結納入後台情境分類與名詞解釋集合頁。

### 優化後功能的操作與介紹撰寫流程

在既有功能操作頁面上更新，並回到操作情境所屬的情境分類目錄，找到功能操作的對應的名詞解釋頁並更新。

e.g. 課程題庫管理增加題目狀態的篩選欄位，則在課程管理介面/課程題庫中找到並更新對應的頁面或是操作流程，回到名詞解釋，中找到**對應使用者分類**：管理者，並在該分類下找到課程題庫的名詞解釋頁，並進行更新。
