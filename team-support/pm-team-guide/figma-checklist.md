# Figma Checklist

確認PM功能描述的完整性：文字、 UI Flow、功能邏輯、頁面狀態等確認已製作的頁面中的 GUI/UI Flow/UX 等是否與 PM 需求一致介面功能操作是否符合PM需求邏輯確認所有 comment 都有被追蹤（解決後關閉）是否包含所有 Mobile 和 App 流程、畫面差異視覺風格是否符合遊戲風格，元件操作是否與其他介面一致後台介面是否與其他後台類似排版、操作有一致性版面上的標題、文字、圖片配置、尺寸、按鈕、間距...是否適配介面的重點是否有被突顯，主次是否分明介面是否能讓使用者正確操作互動，是否有錯誤引導設計若調整了文字，進行討論確認是否提交第二版送翻版本設計若大幅調整介面配置，進行討論確認修改或維持設計若做出和預排會議結論邏輯不同的 draft 設計，PM隨時在群組和RD確認是否可以修改調整 附上介面說明文字/介面狀態在Draft，方便設計檢視畫面有無缺漏PM/設計 draft 版本有共識後，群組請RD確認 draft 是否OK，RD確認後，才製作 Handoff跟運營窗口確認是否需要簡易的 prototype 做業務銷售或內部確認有無大問題Handoff ChecklistPMUX流程操作是否符合需求是否符合當初要求的裝置版本再次確認文字翻譯是否有遺漏或英翻爆版需要下載的檔案是否需要翻譯？提示文字、錯誤訊息是否都有示意圖製作介面開關連動的限制（先開啟Ａ，才能開啟B）其他已存在頁面是否有共通類似的設計，是否遵循通用設計Mobile 和 App 流程、畫面差異 文案用詞避免過於針對特定族群，或僅有少量文字變換除了正常的 ideal 狀態外，確認有支援 empty, partial, loading, complete, error 等狀態檢查不同裝置與解析度的畫面呈現完整的介面說明文字確認 UX handoff 的文字文案用詞避免過於針對特定族群，或僅有少量文字變換，這樣可直接模組化如有文案還未定的地方，請先提示或給出對應長度，讓設計好處理若功能有下載檔案，記得範例檔的文案要一併送翻譯票/figma上的機制是精準描述請避免把系統判斷方式寫得太籠統，這會導致查票時不確定具體設計翻譯需求管理者後台不翻譯，其他都要翻譯。 學習數據目前只翻一半。跟運營窗口確認是否需要內部簡易說明或展示Design
